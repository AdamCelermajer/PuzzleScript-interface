General AVO framework

Implemented: self-contained AVO package, profile loader, evaluator, Codex agent Backend: existing Codex OAuth session

1. Exact definition

An AVO framework is a trusted execution kernel around a persistent autonomous agent.

The agent—not the framework—chooses which candidate to create or revise, which tools to use, and which environment action to test.

EVOframework selects parent → LLM generates once → framework scores
AVOagent researches freely → agent creates xᵢ → agent chooses probe → framework verifies

Necessary condition: if the outer framework tells the model when or how to generate each candidate, it is EVO—not AVO.

3. Complete run loop

profile = load_profile(profile_id, settings)
observation = profile.environment.reset()
task = profile.evaluate(history, observation)

while budget_remains and not task.terminal:
    # Agent has a persistent session and writable workspace.
    context = build_context(
        observation,
        immutable_history,
        admitted_candidates,
        supervisor_events,
        remaining_budgets,
    )

    decision = agent.decide(context)
    # During decide(), the agent may inspect evidence, write tools,
    # create several candidates, revise parents, or run local tests.

    if decision.stop:
        break

    require_legal(decision.action)

    predictions = freeze_before_execution(
        candidate.predict(history, observation, decision.action)
        for candidate in admitted_candidates
    )

    actual = profile.environment.step(decision.action) # exactly once
    transition = append_immutable(before, action, actual)
    evaluations = compare(predictions, actual)
    task = profile.evaluate(history, actual)
    supervisor_events = supervisor.inspect(history, evaluations)
    observation = actual

A probe is legal with zero candidates. The agent may collect evidence before it has a defensible hypothesis.

4. Environment contract

class EnvironmentAdapter:
    reset() -> Observation
    step(Action) -> Observation
    compare(expected, actual) -> Comparison
class EnvironmentProfile:
    objective: str
    environment: EnvironmentAdapter
    evaluate(history, current) -> TaskEvaluation

TaskEvaluation:
    terminal: bool
    success: bool
    score: JSON
Observation:
    payload: opaque JSON
    status: string
    progress: opaque JSON
    available_actions: string[]
    metadata: JSON

The adapter translates transport and data formats. The profile supplies the external objective and the authoritative task evaluator. Neither supplies object names, action meanings, mechanics, a legend, or a solution.

The generic kernel never checks for PuzzleScript values such as WIN. Only the selected profile interprets environment status.

5. Agent contract

Input: AgentContext

  • current observation
  • profile objective and current task score
  • complete transition history
  • candidate summaries
  • available actions
  • supervisor events
  • remaining budgets
  • writable research workspace

Output: AgentDecision

{
  "action": {"id": "ACTION3", "data": {}},
  "rationale": "x_12 and x_17 disagree here"
}

# or
{"stop_reason": "model is sufficient"}

The session stays alive across tool calls. The framework does not restart the model after each probe.

  manifest.json
  predict.py

publish → trusted candidates/x_017/
  manifest.json
  predict.py
  notes.md             # optional
  tests/               # optional

  "schema_version": 1,
  "candidate_id": "x_017",
  "parent_id": "x_012",
  "claim": "ACTION5 changes traversability",
  "complexity": 0.2,
  "command": ["$PYTHON", "predict.py"]
}

The agent authors the package, then explicitly publishes it through the gateway. The command reads {history, current, action} as JSON and returns {expected, confidence, rationale}.

7. Authoritative event order

  1. candidate_registered
  2. agent_decision
  3. prediction_frozen for every candidate
  4. transition containing the real environment result
  5. prediction_evaluated for every candidate
  6. supervisor_event when triggered

A prediction recorded after the transition is invalid and receives no prospective score.

8. Two separate evaluations

Task fitness answers whether the agent solved the environment. It is defined by the selected environment profile and cannot be self-declared by the agent.

Hypothesis evaluation answers whether an optional candidate xᵢ predicts observed transitions.

MetricCalculated byPurpose
Contract validityFrameworkCandidate runs and returns valid data
Replay consistencyFrameworkExplains previous transitions
Prospective accuracyEnvironment comparatorPredicts unseen outcomes
Status/goal accuracyEnvironment comparatorPredicts terminal and progress signals
CoverageFrameworkPenalizes constant abstention
Planning utilityFramework experimentMeasures whether the model supports successful plans
Complexity and costFrameworkPrefers smaller, cheaper equivalent theories

Keep the vector visible. Do not hide all tradeoffs inside one unexplained scalar score.

9. Supervisor and termination

Supervisor triggers

  • repeated no-change actions
  • repeated probes without information gain
  • collective prospective failure
  • ignored contradictions
  • budget exhaustion risk

Run stops when

  • the profile returns terminal = true
  • agent chooses to stop
  • action, decision, candidate, time, token, or cost budget expires
  • a contract violation is unrecoverable

The supervisor sees process evidence only. It cannot edit candidates or supply the hidden solution. Agent stop means only “stop”; success remains the profile evaluator's decision.

10. PuzzleScript implementation

FrameData.frame             → Observation.payload
FrameData.state             → Observation.status
FrameData.levels_completed  → Observation.progress
FrameData.available_actions → Observation.available_actions
GameAction                  ← Action.id
objective = "Win the game."
success   = (FrameData.state == "WIN")
fitness   = (success, levels_completed, -environment_actions)

Not exposed by the adapter: game source, legend, object names, rules, win condition, or solution.
