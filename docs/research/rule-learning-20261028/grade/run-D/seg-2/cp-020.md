  5 dashed ring on grass, 6 dark ring on grass, 7 socket+dark, 8 cage (socket+ring fused), 9 socket+dashed.

- A ring/cage tile becomes plain grass/socket once its ring leaves — this can **connect regions**
  (level 6 depended on this: rings were "doors" between disconnected walkable areas).

## Portal / bar mechanic (all rules live-verified, zero mismatches across 100+ actions)
Entering ring/cage tile R in direction D (approach tile R−D must be walkable):
1. Player freezes at R.
2. Bar center C = R + 2·D (any in-grid tile valid: brick, grass, socket, ring, cage).
3. Ends: e1 = C + rot90cw(D), e2 = C − rot90cw(D); rot90cw(dr,dc) = (dc,−dr).
4. An end on brick / ring / cage is **suppressed** (no ring drawn there).
   Dark ring starts at e1 (at e2 if e1 suppressed); dashed at the other renderable end.
5. While frozen: arrow toward an end swaps dark↔dashed (perpendicular/ suppressed = no-op).
6. ACTION5 commits the dark end: socket→cage (7→8), grass→bright ring (6→3); dashed vanishes (9→4, 5→1);
   player released at R.
Entering a cage first un-cages it (tile becomes socket) and its ring becomes the bar's dark ring.

## Win condition
No bright rings remain (all caged). Consistent on all 6 levels (1, 2, 4, 6, 6, 3 rings).

## Solving approach that worked
1. Transcribe `look` grid; note rings/sockets/player; check walkable-region connectivity.
2. Dijkstra over states (frozenset rings, frozenset cages, player); transitions =
   (walk to approach) + entry + optional flip + commit; cost = #actions.
   Key model subtleties: base() maps initial ring/player tiles to grass (they become walkable);
   renderable end = base grass/socket AND not occupied by ring/cage; flip cost 0 iff dark starts at target.
3. Execute with a **shadow simulator** comparing the model's rendered grid to the real game after
   every action — caught nothing (0 divergences), gave safe stop-on-error.
