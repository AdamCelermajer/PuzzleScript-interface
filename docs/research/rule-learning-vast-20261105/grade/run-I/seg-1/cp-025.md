import sys
from collections import deque

# Level 4 grid, 9 rows x 11 cols
grid = [
"22292222222",
"22212222222",
"21212122211",
"21211112211",
"73411221111",
"21211222111",
"21212222111",
"21222222111",
"21111111111",
]
R = len(grid)
C = len(grid[0])
player = crate = marker = goal = None
for r in range(R):
    for c in range(C):
        t = grid[r][c]
        if t == '7': player = (r,c)
        elif t in ('3','8'): crate = (r,c)
        elif t in ('0','9'): marker = (r,c)
        elif t == '4': goal = (r,c)

def tclass(r,c):
    t = grid[r][c]
    if t == '4': return None  # neutral
    if t in ('1','0','3'): return 'B'
    if t in ('2','9','8'): return 'D'
    return None

def inb(r,c): return 0<=r<R and 0<=c<C

DIRS = {'U':(-1,0),'D':(1,0),'L':(0,-1),'R':(0,1)}

def solve(allow_crate_on_goal=True, allow_push_from_goal=True):
    start = (player, crate)
    prev = {start: None}
    q = deque([start])
    while q:
        (pr,pc),(cr,cc) = q.popleft()
        if (cr,cc) == marker:
            # reconstruct
            path = []
            st = ((pr,pc),(cr,cc))
            while prev[st] is not None:
                st, mv = prev[st]
                path.append(mv)
            path.reverse()
            return path
        pcls = tclass(pr,pc)
        for name,(dr,dc) in DIRS.items():
            nr,nc = pr+dr, pc+dc
            if not inb(nr,nc): continue
            nt = grid[nr][nc]
            if (nr,nc) == (cr,cc):
                # push crate
                if pcls is None and not allow_push_from_goal: continue
                if pcls is not None and tclass(nr,nc) != pcls: continue
                rr,rc = nr+dr, nc+dc
                if not inb(rr,rc): continue
                rt = grid[rr][rc]
                if (rr,rc) == (pr,pc): continue
                if (rr,rc) == (cr,cc): continue
                if rt not in '1209384': continue
                if rt == '4' and not allow_crate_on_goal: continue
                nst = ((nr,nc),(rr,rc))
            else:
                if nt not in '1209384': continue
                ncls = tclass(nr,nc)
                if ncls is not None and pcls is not None and ncls != pcls: continue
                nst = ((nr,nc),(cr,cc))
            if nst not in prev:
                prev[nst] = (((pr,pc),(cr,cc)), name)
                q.append(nst)
    return None

path = solve()
print(len(path) if path else None)
print(path)

# World Model: Class-Locked Sokoban

## Objective and outcome
A single-player, 4-level grid puzzle with a shared budget of 800 actions. In each level, the player walks a single crate onto the blue marker to clear it. The grid is observed as one integer per cell; actions are opaque (directions had to be learned empirically). Best outcome achieved: **WIN, 4/4 levels, 467/800 actions used.**

## Objects and state
Each level is a rectangular grid of varying size (5×5, 6×6, and 9×11 were observed). A cell's value encodes both its **floor class** and the **object** occupying it. Floor classes: **bright**, **dark**, and a special neutral **goal** tile (checkered). Observed codes:

| object \ floor | bright | dark | goal |
|---|---|---|---|
| empty floor | 1 | 2 | 4 (goal, always) |
| marker (crate target) | 0 | 9 | (unseen) |
| crate | 3 | 8 | 10 |
| player | 7 | 5 | 6 |

The player's current class must be read from the player's own number (7 = bright, 5 = dark, 6 = neutral, i.e., standing on the goal); there is no separate player-state field. A crate's class is the class of the floor it currently occupies, so a crate *changes class* as it is pushed across classes (3 ↔ 8 observed repeatedly).

## Controls
- `ACTION1/2/3/4` = move up / down / left / right.
- `ACTION7` = undo the last action.
- `RESET` = restore the current level to its initial player/crate positions.

Every issued action consumes budget, including RESET, undos, and moves that turn out to be blocked.

## Movement and interactions
**Player movement.** The player's class is fixed by the floor beneath it, and the player may step to an adjacent cell only if that cell's floor class equals the player's current class. The neutral goal is the exception in both directions: the player may step onto it from any class and off it onto any class. The goal is therefore the *only* bridge between bright and dark regions; without a goal the player's class never changes. A player may not walk into a crate's cell — entering it is a push, legal only per the rule below; otherwise the move is blocked (state unchanged, action still spent).

**Pushing the crate (the critical rule).** Geometry is standard Sokoban: the player steps onto the crate's cell in one of the four directions; the crate slides one cell further in the same direction and the player ends on the crate's former cell. A push is legal **iff** the crate sits on the neutral goal, **or** the crate's tile class equals the player's current class. The crate's *destination* is unconstrained — it may be pushed onto bright, dark, goal, or marker tiles of any class.

Step by step, a legal push: (1) player on a bright tile adjacent to a crate on a bright tile; (2) player issues the direction toward the crate; (3) crate moves one cell (to any class), player occupies the crate's former bright tile. If the classes differ and the crate is not on a goal, step (3) does not occur: no movement, action consumed.

**Decisive observations.**
- All 24 successful pushes had player-class = crate-class (or crate on goal); one dark player pushing a bright crate was blocked — this observation fixed the rule.
- A crate sitting *on the goal* was pushed successfully, and a player *standing on the goal* pushed a crate: the goal is neutral for pushes, not just for walking. (My first solver wrongly class-locked crates on the goal and reported the final level unsolvable.)

## Goal and level transitions
A level is won by pushing the crate onto the blue marker (code 0 on bright, 9 on dark). Completion happens on that push itself — no extra "stand on goal" condition. After levels 1–3 the next level loads and the same 800-action budget continues. After the fourth level the state becomes `WIN`.

## Undo and history effects
`ACTION7` reverts the most recent action; I used it to back out misreads. `RESET` restores the current level's starting configuration without changing the level index, and costs one action; I used it once in level 3 (recovering from a mis-push) and once in level 4 (escaping a dead end where the crate could only be pushed into an enclosed pocket).

## Remaining uncertainty
- Undo depth/semantics: used successfully, but I never tested how far back it reaches or whether it crosses level boundaries.
- Whether a crate can be pushed off the grid edge (never observed; assumed blocked).
- Codes for marker-on-goal and for a crate resting on a marker during play (unseen).
- Code 11 appeared at the marker cell only in the post-win grid; likely "crate on marker" or a completed-marker indicator — observed once, unconfirmed.
- One unreproduced anomaly: a single expected same-class step briefly registered as blocked and succeeded on immediate retry; no rule impact.
- The code table above is the observed mapping; I make no claim about an underlying arithmetic formula for it.
