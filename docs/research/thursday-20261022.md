# Why does Qwen 3.8 27B fail to learn puzzle games? Status for 22 Oct 2026

Draft, 21 Oct 2026. Sections 4–6 are filled in as today's runs finish.

## Setup

- **Task:** learn an unknown PuzzleScript game from play alone. The agent is given no rules and no goal. It sees each board as a grid of tile ids and as a picture.
- **Game:** Modality, 4 levels.
- **Model studied:** Qwen 3.8 27B, thinking. Reference models are Qwen 3.8 Flash and Qwen 3.8 Max.
- **Agent CLIs:** OpenCode and Codex. Each run is one Docker container.
- **Measure:** the action at which each level is completed, compared with the shortest possible solution (breadth-first search over the game's own rules).

## 1. Provider: is NanoGPT really cheaper than OpenRouter?

**Premise.** We moved from OpenRouter to NanoGPT because it was cheaper.

**Method.**
- Prices come from both providers' model APIs on 21 Oct 2026.
- We applied them to the measured token use of a real game: the mean of 5 games, which is 0.79 M fresh input, 5.80 M cached input and 0.18 M output tokens (output includes reasoning).
- Prices are per million tokens.

| provider · host | precision | input | output | cache read | max reply | cost per game |
|---|---|---|---|---|---|---|
| NanoGPT, auto routing (what we use) | not disclosed | 0.15 | 0.70 | 0.04 | 32.8k | **$0.48** |
| OpenRouter · Alibaba, first party (used on 8 Oct) | not disclosed | 0.425 | 2.55 | 0.085 | 131k | $1.29 |
| OpenRouter · DeepInfra | bf16 | 0.15 | 1.875 | 0.037 | 236k | $0.67 |
| OpenRouter · Near AI | fp8 | 0.04 | 1.35 | 0.018 | 65k | $0.38 |
| OpenRouter · Chutes | fp8 | 0.039 | 1.25 | 0.004 | 65k | $0.28 |

**Conclusion.**
- The premise holds against what we used before. NanoGPT is 2.7× cheaper than first-party Alibaba, and 1.4× cheaper than DeepInfra's full-precision host.
- It does not hold against OpenRouter's cheapest 8-bit hosts, which now cost less than NanoGPT.
- Output tokens are where NanoGPT saves: $0.70 per million against $1.25–2.55.

**Why the OpenRouter bill looked high.** Every 27B run on OpenRouter (30 Sep – 8 Oct) went through Codex, with one game action per request. Codex added little of its own: about 1.2k tokens of tool definitions and 1.3k tokens of system text per request. The size came from resending the whole conversation (up to about 125k tokens of text by the end of a game) and every past picture (up to 125 per request) with each of the 125–176 requests. One game sent about 10 M tokens of text and 4,000–8,000 pictures. So the bill reflected both OpenRouter's price and that turn-by-turn setup.

**Other differences that matter for research.**
- **Which machine answers.**
  - NanoGPT's auto routing does not say which host, or which precision, served a request. Its host list includes 4-bit hosts.
  - OpenRouter names the host, and can be pinned to one.
  - Reproducible runs need a pinned host.
- **Reply length.**
  - NanoGPT caps every 27B reply at 32,768 tokens. This stopped the 27B when it worked as a coach: it thought for 32.7k tokens and wrote nothing.
  - Most OpenRouter hosts allow 65k–236k.
- **Context.** NanoGPT advertises 1M tokens of context, but one game was rejected at about 262k, the limit of the host that served it.
- **Tool calls.** See section 2.

## 2. Q1: Why did the 27B work better under OpenCode than under Codex?

**Premise.** In October, the 27B's tool use looked broken under Codex and fine under OpenCode. Both ran on NanoGPT.
- **Codex** (15 Oct, Baseline+): 11 of the 27B's 25 tool calls came back as plain text instead of a tool call. 9 game decisions were rejected because of this.
- **OpenCode** (20 Oct): 313 tool calls, with 6 malformed-call errors from NanoGPT (2%).

**Question.** Is the cause Codex, the model, or the provider?

**Method.**
1. Read the recorded requests of all 9 old Codex sessions on NanoGPT, and of the 8 Oct Codex run on OpenRouter. This was free.
2. Made 96 direct calls to NanoGPT with no CLI, for $0.11 in total:
   - the same tool, declared four different ways;
   - Codex's real 15 Oct request, sent again.

**Results.**

| test | proper tool calls |
|---|---|
| plain tool, 27B, Chat endpoint (what OpenCode uses) | 16 / 16 |
| plain tool, 27B, Responses endpoint (what Codex uses), short and long tool names | 32 / 32 |
| tool grouped in a "namespace" (how Codex declares MCP tools), 27B | 0 / 16 |
| same, Qwen 3.8 Flash | 0 / 8 |
| Codex's real 15 Oct request, replayed on Responses | 0 / 7 (all "malformed tool call") |
| the same conversation on Chat | 6 / 6 |
| Codex with the same model on OpenRouter (records of 8 Oct) | 63 / 63 namespaced calls |

**Reason.**
- Codex declares MCP tools in a newer, OpenAI-specific format: a "namespace" holding several tools.
- NanoGPT's Responses endpoint does not pass these tools to the model. The model then writes the call as text, or NanoGPT rejects it as malformed.
- This is neither a Codex bug nor a weakness of Qwen: on OpenRouter, the same requests worked.

**Extra context from the host machine.**
- Both old Codex runs carried a 4k-character list of the host's Codex skills (image generation, OpenAI docs, …) in every request.
- The NanoGPT run also carried two of the host's MCP servers as extra tools.
- This extra context did not cause the failures:
  - the OpenRouter run carried the same skills list, and its tool calls worked;
  - today's direct tests carried no extra context, and still failed.
- Codex now runs in Docker with apps, plugins, memories and project docs turned off and a private Codex home, so new runs carry none of it. OpenCode runs never carried it, but OpenCode adds its own 9.7k-character coding-agent prompt.

**Limits.**
- **The behaviour changed over time.** In October the namespace format half-worked on NanoGPT: 13 of the 27B's 23 namespaced calls went through, and all 145 of Flash's. On 21 Oct it never works, so NanoGPT changed something.
- **The CLI is not why levels improved.** The big jump in levels (section 3) came from a different change, who drives the game.
- **No clean CLI comparison yet.** OpenCode vs Codex has not been compared cleanly on a provider where both work.

## 3. Finding: the action budget, not the model, blocked level 4

**Shortest solutions,** by breadth-first search over the game's rules:

| level | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| fewest moves | 6 | 33 | 66 | 158 |

So all four levels need at least 263 moves, more than our budget of 200. Levels 1–3 need 105.

**The 27B driving the game itself:** it acts through a command, with OpenCode, on NanoGPT, with the picture on. All 5 games reached level 3:

| game | notes at the start | level 1 at | level 2 at | level 3 at | extra moves over the best 105 |
|---|---|---|---|---|---|
| base1 | none | 16 | 62 | 182 | +77 |
| inv1 | coach: habits and a planner script | 6 | 42 | 108 | +3 |
| dom1 | coach: game rules | 6 | 40 | 108 | +3 |
| agg1 | coach: both, merged | 6 | 39 | 105 | 0 |
| final | agg1, fresh game | 6 | 39 | 105 | 0 |

- **Level 4 was out of reach.** One coached game computed level 4's optimum itself (158 moves) and stopped: "provably unfinishable this run".
- **Earlier setups.** In every earlier setup, the 27B completed at most level 1 while playing.
- **Limits.**
  - The plain row is a single game.
  - The coached rows share one coach. That coach was Qwen 3.8 Flash, not the 27B.

## 5. Q3: Which help matters: the goal, the rules, a planner, or a method? (runs pending)

**Setup.**
- Each group gets one short, true note at the start. 3 games per group, compared with the no-notes group.
- Where base1 lost its 77 extra moves:
  - level 1: +10, learning the controls and the goal;
  - level 2: +13, learning to push;
  - level 3: +54, learning that a box on a dark floor can only be pushed from a dark floor.

## 6. Q4: Does the 27B really understand the rules? (preliminary)

**base1, no notes.** First correct statement of each rule in its reasoning:

| at move | statement | correct? |
|---|---|---|
| 7 | ACTION1–4 = up/down/left/right, ACTION7 = undo | yes |
| 8 | goal guess: "put the character in the orange frame?" | no |
| 16 | *level 1 solved* | before it could say how |
| 18 | "can't cross from white to dark" | yes |
| 38 | "the person pushes the door like a box (Sokoban-style)!" | yes |
| 62 | *level 2 solved* | |
| 182 | on level 4: "New tile 9 … the goal is probably …" | yes |

**Its end-of-game world model** (no help) is correct, with one wrong generalisation: "the robot can always step onto the goal". This holds on levels 1–3, where the goal is on white, and fails on level 4, where it is on dark.

**Solvers.** The solver each coached game wrote at the end solves all 4 levels in the fewest moves, when run afterwards. Its harness already contained a planner, and it had seen level 4, so this is not a held-out test.

**Pending.**

- Statements labelled against the rules.
- Moves checked against what the model said.
- Its own solver tested on the unseen level 4.
