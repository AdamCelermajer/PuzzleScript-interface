Real-time tasks for a slow reasoner

Adam Celermajer · 22 October 2026 · reserve material for the discussion; not part of the proposal

1. The idea in three lines

Idea
The slow LLM coding agent does not play the game. It works out the rules and writes small fast artifacts: Python controllers for reflexes, and typed decision questions (Jev-style "System One" calls) for judgements. It goes back to thinking only when a monitor reports that the controllers are failing, and it repairs them while they keep running.
Why now
Typed-decision models arrived in the last five weeks: Jev (closed), OpenAI and Microsoft endpoints, and at least three open ones built on Qwen3.8-27B. They answer in 50–300 ms. By their own model cards they cannot drive motors or win games alone; code can, and coding agents already write such code offline.
In one line
Harness² taken to real time: the coach edits the player's controllers instead of its harness, while the clock keeps running.

B. The LLM writes the fast thing: controllers as code

D. Escalation, deferral and repair triggers
System Switch (Bailo, 2610.09683) V7 Oct 2026Closed-loop Doom that keeps running while a reasoning VLM deliberates; the fast typed actor defers its least-confident 30% of decisions. Offline, deferral gains track the actor's AUROC (ρ = 0.87). In closed loop (33 games × 3 seeds) no variant reached the exit; committed plans opened doors but froze the actor.The nearest test of confidence-gated escalation under a clock, and it fails. The reasoner returns plans, not repaired code; the trigger is confidence only, not mismatch, novelty or stall.

Mismatch-triggered wake-ups: PreAct (Jun 2026), MonTA (Nov 2024, v2 Jan 2026), Bayesian partner modelling (Aug 2026), Adaptive Code Generation for Controlling Robots (ISoLA 2026) V2024–26PreAct compiles a successful GUI run into a screen-checking state machine replayed with no LLM calls (8.5–13× faster); a screen mismatch returns control to the agent. 3. The gap

On 15 October the gap looked wide. It is narrower now, and this is the honest statement. Every ingredient exists somewhere, most of it published in the last four weeks: a coding agent that learns a game's rules by interacting and ships a player that runs with zero model calls (Compiled Agency, 26 Sep; Code to Control, 30 Sep); a rulebook compiled to code and repaired on prediction error, with the world paused (Memento 3, 8 Oct); a slow reasoning model teaching a fast decision model that acts alone under a wall clock, by text and between attempts (TORSI, 14 Oct); confidence-gated escalation from a fast actor to a reasoning model while Doom keeps running, which did not reach the exit (System Switch, 7 Oct); and failure-triggered LLM patches of a running behaviour-tree library behind an admission gate, in a lockstep simulator (Self-Crystallizing BTs, 18 Oct, unreviewed). What nobody has done, as far as we found on 21 October, is the combination: in a game whose rules the agent does not know and whose clock does not stop, (a) learn the rules, (b) compile them into executable controllers plus typed questions, each with declared preconditions and predicted effects, (c) repair or replace those controllers during the episode, asynchronously, while the fast layer keeps acting, triggered by the agent's own world model being contradicted rather than by confidence alone, and (d) report the latency–quality–cost frontier against the paused-LLM upper bound. What remains ours beyond the combination: code as the artifact, with tests and predictions; repair while acting; unknown and uncontaminated rules; and the same games as the turn-based thesis. A reviewer will call it "Compiled Agency plus TORSI plus a monitor". The answer is the measurement: nobody has measured whether repair during play beats repair between attempts under a clock, and System Switch suggests the obvious trigger does not work.

Closest workWhat it does instead
RealtimeBench / TORSI (14 Oct 2026)The teacher writes text guidance for a Jev student, offline between attempts, in six well-known games. No code, no tests, no trigger during play, and the student cannot do anything the guidance did not anticipate.
Compiled Agency (26 Sep 2026); Code to Control (30 Sep 2026)A coding agent learns by interacting and compiles code, then the program is frozen: no clock during development, no monitor, no repair after the freeze. Code to Control refits constants offline when dynamics change and cannot trigger a structural edit.

Also close, but turn-based: Memento 3 (rulebook → code, repaired on prediction error), Twin (no action until the program reproduces every observed transition), Tycho (decides when to construct, repair, use or bypass the model).

5. Shortlist and first experiment

Shortlist
(1) PuzzleScript real-time, deterministic subset first, stochastic second: continuity and unknown rules. (2) The six Code-to-Control Atari games, run through System1-Arena's real-time harness: exact baselines on both sides, for the ML audience. (3) RoboCup 2D only if Gal supervises; otherwise the MuJoCo pick-and-place study as the robotics-flavoured side piece.
Week 1
Audit the candidate games by play (today's reading: Pushcat Jr, Boxes & Balloons, Sneeze and Magik move things on the clock; Oskar's Maze and Some Lines look like animation only; Beam Islands unchecked). Add TICK and the clock driver. Write the minimal arbiter: controllers with precondition / act / predict, hot reload on version bump, deadline with fallback, escalation through a file queue the harness reads. Write the tick log.
Week 2
Four games × slowdown {8, 4, 1} × 2 seeds, one frontier harness. Conditions: B0 paused LLM every tick (upper bound); B1 live LLM every tick with a no-op when late; B2 controllers written once and frozen (Compiled Agency / Code to Control shape); B7 TORSI-style, a teacher writes text guidance for a decision model between attempts; C1 code controllers with repair during play; C2 = C1 plus one typed question ("which controller?" or "is the player in danger?") answered by a self-hosted 27B decision model. Trigger ablation inside C1: confidence only (System Switch shape) against prediction mismatch and stall.
Deliverable
One figure: levels solved against slowdown per condition. One table: p95 latency, deadline misses, calls per minute, escalation precision. Five annotated escalation-and-repair episodes.
Cost
CPU for the games. About $6 per hour for the vast box, shared by all games and by the decision model. Or $5–30 per game on a frontier harness.

6. How it connects to the current thesis

Same model
JEV-27B-VL, Decision-2.0-Vega-27B and Clef are all adapters or fine-tunes on Qwen3.8-27B, the thesis model. The FP8 server already running on the vast box uses vLLM; the JEV card ships a vLLM serve_decide.py. Serving one of them next to the chat model is plausible and untested.
Same stack
The same games, runtime, harness container and agent_events.jsonl. The tool gateway's checkpoint / restore becomes the controller test bench. The rule-learning output of the thesis becomes each controller's predict(), which is what the monitor checks.
Same loop
Harness² is "an improver edits the player's harness files from contrasts between scored runs". Here the improver edits controller files from contrasts between ticks, while the game runs. AVO's evaluator becomes the per-controller score. TORSI is Harness² with a decision model as the player; we add code and a trigger during play.
What changes
Latency becomes a first-class metric. The proposal does not change: the committee review of 19 Oct recommends keeping this out of the document and holding one reserve slide.

7. Open questions

  • Is repair while the clock runs worth more than repair between attempts? TORSI's validation gate rejects bad updates between attempts; repair during play needs shadow testing to be as safe.
  • System Switch: confidence-gated escalation under a live Doom clock reached the exit in no run. Why would a mismatch trigger with code repair do better? That is the first thing to test, not to assume.
  • Compiled Agency shows frontier coding agents already compile strong zero-call players from bare interaction. Repair during play only matters where the environment changes or cannot be explored offline. Choose games where that is true.
  • How much of any gain is the controller, and how much the fallback? "Good Judgment, Bad Advice" used a placebo controller; we need the same.
  • Which decisions in a small grid game belong to a typed model at all? In System1-Arena, small System-1 models rarely succeed in closed loops.
  • Contamination: PuzzleScript games are obscure, Atari is not. A reviewer will ask for both.
