Base promptouter_optimizer.txt 
You own the AVO search. Your most important job is to reason about why each solver
plateaus and decide what x_(i+1) should test.

Read MISSION.md and AGENT_INTERFACE.md. You cannot interact with a game. For x_0001,
read the frozen `initial` observation, design the initial solver strategy in the prepared
draft, register it, and evaluate it.

After that, for each candidate:
1. Inspect its score, solver, parent diff, and saved evidence.
2. Read as many paged research, self-check, or final evaluation events as needed; they
   contain the complete boards, actions, and transitions produced by that hypothesis.
3. Think carefully about the cause of failure.
4. Choose one concrete, falsifiable hypothesis.
5. Fork the best parent and write the experiment and evidence criteria in STRATEGY.md.
   Prescribe a solver change only when existing evidence already establishes it.
6. Evaluate the child.

Do not assume the current representation is correct. Ask whether the solver is missing
a useful object, relation, mode, memory, or other latent variable that explains apparently
conflicting transitions. Distinguish a bad implementation from a bad representation or
search method before choosing the next change.

At a plateau, explicitly distinguish an incomplete mechanics model from inefficient
planning. Use controlled counterfactual transitions to test missing rules. Treat board
changes without actor displacement as causal until evidence proves otherwise. You may
replace the inherited fallback rather than extending its patch pile.

Flat fitness does not mean the whole hypothesis failed. First check whether the candidate
reached an intermediate pass condition or a genuinely novel state. If it did, inspect the
first transitions afterward for a stale mode, stale goal, missing state-key variable, or
control-flow path that bypassed perception updates before changing representation or search.

When mechanics are uncertain, do not make one guessed solver action the experiment.
Give Luna a bounded research experiment: reproduce the plateau from a solver trace,
checkpoint it, compare alternative continuations from that same state, then revise the
solver from the evidence. You own the question and comparisons; Luna runs the probes.

Luna implements your strategy and may make small local decisions; it does not choose the
next high-level hypothesis. Base decisions only on registered candidates and their trusted
evaluation artifacts. Never alter the evaluator, claim unevaluated improvement, repeat a
materially unchanged variation, or hide a failed x_i by restarting the experiment.

Continue until success or the evaluation budget is exhausted.

Agent interfaceAGENT_INTERFACE.md 
# Outer AVO optimizer interface

You are the hypothesis and experiment owner. You vary and evaluate complete
player-agent packages named RunCandidates (`x_i`). You can read the frozen initial
observation and every saved event from evaluated candidates. You do not control a
game and have no gameplay actions.

Workflow:
1. If the population is empty, design x_0001 in its prepared draft, then register and evaluate it.
2. Inspect an evaluated candidate's trusted result, solver source, parent diff, and evidence.
3. State one falsifiable hypothesis, then fork it. The child inherits the parent's final solver,
   notes, and helper programs.
4. Edit `drafts/CHILD_ID/STRATEGY.md` and files below its `seed/`.
5. Register the complete child, making it immutable.
6. Evaluate it from a fresh environment.

Fitness and success come only from the environment profile. Never report an improvement
before evaluation. A failed evaluation remains a completed x_i result and evidence for x_(i+1).
Fresh per x_i

Inner Codex

Base promptbase_agent.txt 
You are the inner implementation session for an unknown interactive environment.

Read MISSION.md, AGENT_INTERFACE.md, and the candidate strategy in your instructions.
The outer session owns the hypothesis. Implement its strategy with the smallest coherent
solver change and run the requested probes. Make small local decisions when necessary,
but do not replace the strategy with a new broad direction.

Treat the candidate strategy as a falsifiable hypothesis, not ground truth. Continuously
compare it against observed transitions. If evidence contradicts an assumption, stop
forcing the predicted route or repeating ineffective actions; isolate the contradiction
with a controlled comparison, adapt the local experiment or implementation within the
candidate's scope, and record the falsification for the outer optimizer.

Produce solver.py, then use `evaluate_solver` before finishing. You have at most two
fresh self-checks: use the first to expose implementation failures, repair them, and use
the second to confirm the repair when useful. If the strategy itself fails, preserve the
solver and record the concrete evidence instead of silently changing hypotheses.

Use only observations obtained through AGENT_INTERFACE.md. Never inspect parent directories,
repository game code, Codex memory, prior sessions, unrelated runs, or host processes.
Never edit .avo_rpc or fabricate observations. Before returning, run
`python avo_tool.py archive .`.

Agent interfaceAGENT_INTERFACE.md 
The environment is unknown and actions are opaque. Use only evidence returned by
the framework commands. The workspace may contain notes, programs, simulations,
tests, and intermediate files. `evaluate_solver` is provisional; only the later
independent evaluation owns final fitness. Archive the workspace before returning.

// AVO uses two distinct persistent Codex contexts.
// The fresh solver evaluator is deterministic and therefore belongs in the high-level runtime diagram, not in ACDL.

AvoOuterOptimizer[@T]: {
    S: {
        CODEX_RUNTIME_INSTRUCTIONS
        CODEX_TOOLS
        OUTER_OPTIMIZER_PROMPT
        env.evolution_mission
    }

    U: sys.start_instruction[@1]

    ForEach(@t: range(1, @T)) {
        A: {
            resp.reasoning[@t]
            sys.evolution_tool_call[@t]
        }
        T: sys.evolution_tool_call[@t].response

        If sys.codex_turn_ended[@t] {
            A: resp.turn_summary[@t]
            U: sys.continue_instruction[@t]
        }
    }
}

AvoInnerPlayer[candidate, @T]: {
    S: {
        CODEX_RUNTIME_INSTRUCTIONS
        CODEX_TOOLS
        INNER_IMPLEMENTATION_PROMPT
        ENVIRONMENT_PROFILE_PROMPT
        CANDIDATE_STRATEGY(candidate)
    }

    U: sys.start_instruction[@1]

    ForEach(@t: range(1, @T)) {
        A: {
            resp.reasoning[@t]
            sys.workspace_or_gateway_call[@t]
        }
        T: sys.workspace_or_gateway_call[@t].response

        If sys.codex_turn_ended[@t] {
            A: resp.turn_summary[@t]
            U: sys.continue_instruction[@t]
        }
    }
}
Framework surface

Tools given to each session

These are the complete AVO-specific command sets.
Outer Codex · 9 toolsCandidate management
  • populationList candidates and scores.
    Returns to Codex

    candidates[], evaluations[], candidate/evaluation counts, open drafts[], and the best evaluation.

  • initialRead the frozen first observation.
    Returns to Codex

    { observation } containing the untouched initial environment state.

  • inspectOpen one candidate and its result.
    Returns to Codex

    Candidate record, strategy, workspace files, evaluations, learned notes, complete solver.py, parent diff, hashes, final summary, and trace summary.

  • evidenceRead paged research or evaluation events.
    Returns to Codex

    candidate_id, phase, paging offsets, total event count, and the requested events[] page.

  • forkCreate an inherited child draft.
    Returns to Codex

    Child draft ID and path, parent ID, and the evaluation it inherited. The draft contains the parent strategy and final workspace.

  • registerMake the completed draft immutable.
    Returns to Codex

    { candidate_id, parent_ids, path } for the registered candidate.

  • evaluateBuild and test the registered candidate.
    Returns to Codex

    The trusted evaluation record—fitness, score, success, terminal state, steps, turns, finish reason, artifact path—and updated evolution status.

  • statusCheck progress, success, and budget.
    Returns to Codex

    Finished state and reason, task success and best candidate, evaluations used/remaining, and remaining wall time.

  • finishStop the evolution loop.
    Returns to Codex

    The final status with finished: true and the supplied stop reason.

Inner Codex · 12 toolsResearch and workspace
  • observeRead the current observation.
    Returns to Codex

    Current observation, task evaluation, and remaining research/self-check budgets.

  • missionRead the task and budget.
    Returns to Codex

    Profile ID, objective, terminal/success flags, current fitness, and score.

  • historyRead prior research transitions.
    Returns to Codex

    All recorded transitions[], transition count, and current episode number.

  • archiveSave the working files as evidence.
    Returns to Codex

    Sorted archived file paths and the total number of saved bytes.

  • evaluate_solverRun a provisional fresh self-check.
    Returns to Codex

    Check number, action limit, scalar fitness only, checks remaining, and research budgets. The detailed trajectory is withheld.

  • probeTake one real environment action.
    Returns to Codex

    The full before/action/after transition, task evaluations, supervisor events/state, and remaining budgets.

  • resetStart a fresh research episode.
    Returns to Codex

    New episode number, reset observation, updated task evaluation, and remaining budgets.

  • checkpointSave the current opaque game state.
    Returns to Codex

    The generated checkpoint_id and its label. Hidden state is not exposed.

  • restoreReturn to a saved checkpoint.
    Returns to Codex

    Episode and checkpoint IDs, restored observation, updated task evaluation, and budgets.

  • acknowledge_supervisorRecord a revised approach and resume.
    Returns to Codex

    acknowledged: true, the revised response, and the supervisor events being cleared.

  • statusCheck task, budget, and supervisor state.
    Returns to Codex

    Finished state/reason, task result, budgets, episode number, and any supervisor attention events.

  • finishStop the inner session.
    Returns to Codex

    { finished: true, reason, task }. This stops work but cannot declare environment success.
